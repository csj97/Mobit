# 선물 모의거래 작업 인수인계

최종 정리: 2026-10-07. 이 문서는 다른 컴퓨터·새 세션에서 저장소를 pull한 뒤 작업을 재개하기 위한 시작점이다. 아직 출시 QA 완료 상태가 아니다.

1. 저장소 루트의 [AGENTS.md](../AGENTS.md).
2. 이 문서 전체: 최신 UI 요청, 실제 구현 상태, 다음 작업 순서를 먼저 확인한다.
3. [구현 계획](futures-agent-implementation-plan.md)의 「최신 확정 정책: KRW 전용 선물 및 청산 회계」 및 2026-10-02의 리뷰/화면 흐름 기록.
4. [시나리오 문서](futures-paper-trading-plan.md)의 최신 확정 정책.

이전 문서의 해외 USDT·수수료/MMR·BTC 선물·UI 미연결·시세 만료 시 `-` 표시 설명은 당시 기록이다. 아래 확정 정책과 최신 사용자 요청을 우선한다. 과거 테스트 통과 수는 새 세션의 현재 코드 검증을 대신하지 않는다.

## 2. 반드시 유지할 확정 정책

- 업비트·빗썸 **현물 시세를 사용하는 MOBIT 내부 선물 모의거래**다. 실제 거래소 주문을 전송하지 않는다.
- 거래소별 선물 KRW 계좌는 독립되고 신규 잔액은 0원이다. 현물 자산·거래내역과 섞거나 이체하지 않는다. 국내 KRW 광고 보상은 1,000만 원이다.
- 현물 KRW/BTC 기능은 유지하고 선물에는 KRW만 제공한다. 해외 거래소, USDT 광고 1,000, Cross/Isolated는 후속 범위다.
- 최대 레버리지: BTC/ETH 100배, SOL/XRP/ADA/AVAX/NEAR/SUI/DOGE/SHIB/LINK/UNI/AAVE/RNDR 50배, 그 외 20배. RNDR을 유사 종목명으로 대체하지 않는다.
- 수수료·펀딩·MMR은 적용하지 않는다. 증거금이 소진되는 경계(-100% 도달 포함)에서 청산하고 다른 가용 잔액/현물 자산에 초과 손실을 부과하지 않는다.
- 같은 거래소·마켓은 활성 포지션 하나이며 추가 진입은 같은 방향·배율일 때만 허용한다. 최초 진입 시각과 개별 체결 이력을 보존하고 추가 진입 전 과거 조건을 검증한다.
- 청산/종료 결과·잔액·거래내역·실현 PNL·검증 시점을 원자 저장한다. 실패한 구간을 건너뛰거나 정산을 중복하지 않는다.

## 3. 최신 사용자 UI 요청 — 되돌리지 말 것

- 금액·가격·수량은 현물/선물 모두 `TradingNumberFormat`으로 표시한다. 절댓값 1,000 미만은 소수점 최대 8자리, 1,000 이상은 소수 부분 절삭과 콤마를 적용한다. 기존 100 기준은 폐기한다. 계산·저장 원본은 보존하고 증거금 직접 입력/비율 선택만 이 규칙으로 정규화한다. 수익률 `%` 자릿수는 기존대로 유지한다.
- 기존 Main/Trade/Investment/PNL 디자인을 유지하고 선물에 맞는 내용만 연결한다. 첨부 거래 앱의 미지원 기능을 추가하지 않는다.
- 메인 선물 모드에서는 BTC 마켓 탭만 제거하고 보유/관심 흐름을 유지한다. 공포·탐욕 버튼은 현물/선물 스위치 옆에 둔다.
- 주문 탭/버튼은 `롱 · 숏 · 거래내역`, `롱 진입`, `숏 진입`, `포지션 종료`다. 버튼에 긴 처리 설명을 넣지 않는다.
- 레버리지 슬라이더는 0/20/40/60/80/100% 지점의 원, 선택 위치까지 강조된 선과 원, 단계 이동 시 약한 햅틱을 사용한다. 아래 숫자 라벨은 표시하지 않으며 선은 양 끝 원 바깥으로 연장하지 않는다. 실제 배율은 최소 1배부터 종목 상한까지다.
- **시세 누락·검증 중에도 마지막 금액을 유지한다. 숫자를 `-`/`—`로 바꿔 깜빡이게 하지 않는다.**
- 재실행 시에는 저장된 마지막 검증 가격, 없으면 평균 진입가로 임시 평가한다. 이는 표시용이며 주문 체결 가격으로 재사용하지 않는다.
- 평소 사용자는 수익률·평가손익을 보면 된다. 조회/검증/체크포인트/참고 평가 설명을 계속 노출하지 않는다. 정상 투자내역의 안내 footer도 숨긴다.
- 백그라운드 검증 중이라는 이유만으로 주문 버튼을 비활성화하지 않는다. 사용자 요청 시 기존 주문 UseCase에서 필요한 가격/청산 검증을 수행하고, 진행 중인 자동 검증은 내부적으로 기다린다. 실패하면 주문을 저장하지 않는다.
- 계좌 읽기 실패·주문 처리 중·종료된 포지션·방향 불일치 같은 실제 조건은 제한하거나 필요한 안내를 표시한다. 중복 요청은 막는다.
- 여러 줄 Swift 인자/파라미터는 여는 괄호 다음 줄부터 하나씩 쓰고 닫는 괄호도 별도 줄에 둔다. 들여쓰기는 Xcode 설정을 따른다.
- 파일명 자체에 디렉터리 경로를 붙이지 않는다. 실제 Scene/Views/Reactors/Coordinator 폴더 배치를 사용한다.

### 최근 리뷰 4건 해결

1. 업비트 8일 뒤 복귀한 밀리초 진입: 진입 초 내부의 복원 불가능한 부분만 종가로 보완하고 이후 초봉의 고가/저가로 급변·회복 청산을 검증한다. 전체 첫 분을 종가로 덮지 않는다.
2. 메인 선물 자산 요약/보유 목록에서 현물 데이터와 다른 거래소 포지션을 제외했다.
3. 투자내역·주문 화면 방문 전에 더보기로 충전해도 선물 계좌 준비/지급이 가능하다.
4. PNL 공유 이미지/문구에 거래소·선물·KRW를 포함했다.

### 혼동하면 안 되는 구현 한계

- 자동 검증은 foreground/주기 REST와 수신 소켓의 현재가 청산을 병행한다. MainReactor/TradeReactor가 수신한 국내 KRW tick의 거래소·체결 timestamp를 전달한다. 해당 종목 소켓이 구독되지 않거나 앱이 비활성인 동안 모든 시세를 수신하는 구조는 아니다. REST 정상 결과 후 약 3초, 작업 한도 보류 1초, 요청 실패/자료 누락 15초 재시도는 유지한다.
- 유효한 최신 현재가로 증거금 소진이 확인되면 과거 조회 완료를 기다리지 않고 원자 정산한다. `observedAt`을 별도 보존하고 `verifiedThrough`는 진행시키지 않는다. 청산 가능 구간은 마지막 검증 경계부터 관측 시점까지이며 최초 도달 시각을 관측 시각으로 단정하지 않는다. 안전한 현재가만으로 과거 급변·회복 청산을 생략하지 않는다.
- 재접속은 현재 가격만으로 판정하지 않는다. 미접속 중 청산 경계에 도달했다가 회복했을 수 있어 과거 구간 검증을 유지한다.
- 실시간 수신 가격은 메모리에 보관하며, 재실행 시에는 저장된 마지막 검증 가격을 복원한다. 모든 수신 tick을 디스크에 저장하는 구현은 아니다.
- 새 청산 저장 성공 뒤 Scene의 앱 내부 배너로 거래소·종목·방향·배율을 안내한다. 동일 포지션의 중복 tick은 다시 정산/발행하지 않는다. OS 로컬 알림/FCM은 추가하지 않았다. 앱 강제 종료와 배너 표시 사이의 전달 보장·영구 미확인 알림함은 구현하지 않았다.
- `canRequestOrder`는 사용자 주문 요청 가능 조건이고, 실제 실행 허가는 주문 preflight가 검증한다. 기존 `canSubmit`은 마지막 검증 결과에 대한 판정이므로 다시 버튼 활성화 조건으로 연결하지 않는다.

## 5. 다음 작업 순서와 완료 조건

### 우선 1: 실제 국내 흐름과 조용한 UI 확인

- [ ] 빗썸에서 0원 계좌 → 더보기 광고 충전 → 롱/숏 진입 → 같은 방향/배율 추가 진입 → 전량 종료 → 투자내역/PNL/공유를 수동 확인한다.
- [ ] 업비트/빗썸 및 현물/선물 전환 후 자산/보유/내역이 섞이지 않는지 확인한다. 현물 BTC와 선물 포지션을 함께 가진 경우를 포함한다.
- [ ] 검증/시세 실패 중 숫자와 버튼이 깜빡이지 않고 불필요한 상태 문구/빈 안내 영역이 나타나지 않는지 확인한다.
- [ ] 초기 검증 중 주문 요청, 긴 대기, 네트워크 실패, 화면 이탈/백그라운드 전환 및 연속 탭을 확인한다. 오래 기다린 주문이 의도치 않게 나중에 실행되는지, 주문 처리 표시/실패 안내가 적절한지도 점검한다.
- [ ] 실제 청산 후 열린 주문 화면/보유 목록/투자내역/PNL/잔액이 일관되게 갱신되는지 확인한다. 필요하면 청산 결과를 한 번만 알려주는 최소 UI를 보완한다. 반복 검증 메시지로 대체하지 않는다.

### 우선 2: 장기 미접속·시세 검증

- [ ] 실제 가격 자료로 급변 후 회복, 밀리초 진입, 초/분 경계, 무체결 구간, 업비트 초봉 보존 기간 안/밖을 재생한다.
- [ ] 빗썸 체결 페이지 경계/완전성/기간 제한과 실제 장기 복귀 흐름을 확인한다. 조회 오류나 누락을 정상 무체결 또는 종가 fallback으로 처리하지 않는다.
- [ ] 검증/정산 중 종료·충전·앱 강제 종료 및 재실행 후 체크포인트/잔액/내역의 중복·누락 여부를 확인한다.
- [x] 소켓 수신 현재가 청산과 REST 현재가 청산을 연결했다. 저장소 잠금/최신 포지션 재검사로 충전·종료와의 충돌을 방지한다. 실제 두 거래소의 시세 수신·배너 전체 수동 확인은 남는다.

### 우선 3: 광고와 화면 출시 QA

- [ ] 실기기 보상 광고 성공/닫힘/로드 실패/중복 콜백/저장 실패 후 재실행을 확인한다. 충전 대상 계좌를 광고 시작 시 고정하고 현물이나 다른 거래소에 지급하지 않는다.
- [ ] iPhone SE와 작은 화면, 소프트웨어 키보드, 큰 글씨, 영문, 라이트/다크, VoiceOver를 확인한다. 슬라이더 이동/끝 원/햅틱과 PNL 공유의 거래소 헤더를 포함한다.
- [ ] 광고 중 key window/Scene 상태 변경으로 로딩 제거 대상을 놓치는 코드를 수정했고 화면 분리 후 제거 테스트를 추가했다. 최초 광고 종료 후 실제 잔류 현상이 같은 원인인지는 실기기 재현 확인이 필요하다.
- [ ] 기존 「하루 1회 앱 실행 전면광고 복원」 요청은 이 변경의 보상 광고 준비와 별개다. 이번 검증/커밋 설명에서 복원 완료로 포함하지 않는다. 필요 시 전면광고 실제 진입점/주석/노출 정책을 다시 확인한다.

### 별도 정책 확인 후 진행할 항목

- 누적 충전 금액 표시: 사용자가 자신의 입금/충전 총액을 알고 싶다는 의견이 있었다. 현재 보유 자산 중 충전 비중과 누적 충전액은 다르므로 자동으로 같은 의미로 구현하지 않는다. 초기 지급 포함 여부, 계좌별 범위, 기존 사용자 데이터 복원 가능성, 이익 계산 정의를 확정한 뒤 진행한다. 이번 UI 변경에서 완료한 기능이 아니다.
- 해외 거래소·USDT·Cross/Isolated·수수료/펀딩/MMR은 현재 국내 범위 완료를 위해 추가하지 않는다.
